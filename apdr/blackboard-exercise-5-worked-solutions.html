Exercise 5.1: Recursion

5.1.1 Define recursion

Try first: Define recursion in fewer than three sentences, including how a recursive process stops.

Attempted it? Open the worked steps

5.1.1 Define recursion · worked solution

  1. Recursion solves a problem by having a function call itself on a simpler instance of the same problem; a base case answers directly, and each recursive case must make progress toward it.

  2. Check: the definition includes both the self-call and the stopping case, so it rules out a call that repeats forever without getting simpler.

5.1.2 Complete the factorial function · worked solution

  1. Use the course's positive-integer convention for this version: factorial(1) is the base case, and for x > 1 the recurrence is x! = x · (x − 1)!.

  2. Fill the blanks with 1, 1, and 1:

    def factorial(x):
    if x == 1:
        return 1
    return x * factorial(x - 1)

  3. For factorial(5), calls descend to factorial(1); then the waiting calls return 1, 2, 6, 24, and 120.

  4. The sheet does not specify whether zero is an allowed input. If the function must also accept zero, use x == 0 as the base case and return 1, which follows the convention 0! = 1.

  5. Check: the argument decreases by one on each call, so every positive integer input reaches 1; the value then multiplies back up.

5.2.1 Continue the triangle pattern · worked solution

  1. Start at n = 0 with one solid triangle. At every next step, split each black triangle into four equal smaller triangles and keep the three corner triangles black; the middle triangle stays blank.

  2. So the counts at the requested steps are:

    Step nBlack trianglesConstruction
    01One solid starting triangle.
    13Three black corner triangles.
    29Each of the 3 black triangles produces 3 black corners.
    327Each of the 9 black triangles produces 3 black corners.

  3. For the drawing, repeat that replacement inside every black triangle at n = 1 to obtain step 2, then repeat it inside all nine black triangles to obtain step 3. Previously empty central triangles remain empty.

  4. Check: the number triples at each step, and the large central gaps remain blank rather than being recoloured.

5.2.2 Write a recursive triangle counter

Attempted it? Open the worked steps

5.2.2 Write a recursive triangle counter · worked solution

  1. Let black_triangles(n) return the number at step n. The domain is a non-negative integer step, and step zero contains one black triangle.

  2. For n > 0, each black triangle creates three black corner triangles, so the total is three times the previous step's count:

    T(0) = 1,   T(n) = 3 · T(n − 1)

  3. That recurrence gives a fully recursive implementation:

    def black_triangles(n):
    if n == 0:
        return 1
    return 3 * black_triangles(n - 1)

  4. The base case returns directly. Each recursive call reduces n, and the returned smaller count is multiplied by three on the way back.

  5. Check: black_triangles(0) returns 1 and black_triangles(1) returns 3, matching the first two drawings.

5.3.1 Recursion and repetition

Attempted it? Open the worked steps

5.3.1 Recursion and repetition · worked solution

  1. Recursion repeats work through a function calling itself on a smaller problem, whereas repetition repeats a block with a loop.

  2. Check: both can perform work repeatedly; the distinction is how the next repetition is expressed.

5.3.2 Write the recursive dream function · worked solution

  1. Assume level 0 means awake, current_level is the level the dreamer is in now, and the helper's level argument names the destination level. Start with dream(0, max_level), where max_level is non-negative.

  2. The recursive case enters the next deeper level with play_lullaby(current_level + 1), then calls dream for that level. The base case runs do_important_job() once at the maximum level.

  3. When the deeper call returns, kick(current_level) wakes the dreamer to this call's level. That line runs after the recursive call, so it executes on the way back up the call stack.

  4. Here is one complete version. It rejects a maximum below the current level, returns totems only from the outer awake-level call, and checks the totem after the last upward transition:

    def dream(current_level, max_level):
    if current_level < 0 or max_level < current_level:
        raise ValueError("expected 0 <= current_level <= max_level")

    if current_level == max_level:
        do_important_job()
    else:
        next_level = current_level + 1
        play_lullaby(next_level)
        dream(next_level, max_level)
        kick(current_level)

    if current_level == 0:
        return check_totem()

  5. For dream(0, 3), the calls go 0 → 1 → 2 → 3. The job runs at 3; returns then call kick(2), kick(1), and kick(0). Once awake at 0, check_totem() runs.

  6. Check: play_lullaby runs once per downward move, kick once per upward move, the job runs once at the maximum, and the totem check runs only after the outermost call wakes.
