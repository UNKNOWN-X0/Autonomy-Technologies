7.1 Memory models and variables

A program manipulates names, values, and objects. Distinguishing them explains aliasing, lifetimes, and the different abstractions exposed by C++ and Python.

In plain words: a name is how code refers to a value or object. In Python, assignment binds a name to an object; two names can refer to the same mutable object. C++ assignment to an ordinary value usually copies it, while a reference or pointer can provide another route to an object.

Python binding and mutationb = a binds b to the object currently named by aRead it as: “b now refers to the same object as a”. Mutating that shared list is visible through either name; rebinding one name does not rebind the other.

Worked trace · shared list

  1. a = [1, 2] creates a list object and binds a to it.
  2. b = a binds b to that same list; there are still two names and one list.
  3. b.append(3) mutates the list, so both names observe [1, 2, 3].
  4. b = [9] rebinds b; now the names refer to different lists.

C++ examples often describe automatic local objects as “on the stack” and dynamic allocations as “on the heap”. These are useful implementation pictures, not a language guarantee that every local occupies a hardware stack. In Python, object storage is managed by the implementation; call frames hold local bindings. Do not infer exact physical placement from the source syntax.

In C++, a pointer stores an address and can be null or invalid; dereferencing an invalid pointer is undefined behaviour. A reference aliases an existing object and cannot be reseated. Python hides raw addresses and pointer arithmetic from ordinary code.

Trap: assignment is not always a deep copy. Check whether the operation copies a value, copies a reference, or mutates an object.

Near miss: two variables holding equal lists need not share one list. Equality compares contents; identity asks whether they are the same object.

7.2 Types and polymorphism

A type system determines which operations are permitted and when errors are detected. Polymorphism lets one piece of code work with different values through shared operations.

In plain words: static typing checks types before a program runs; dynamic typing checks what an operation can do at runtime. Neither means that a language has no type rules.

Three common forms of polymorphismAd-hoc · Parametric · SubtypeRead it as: “separate implementations, one generic implementation, or one subtype used through a parent interface”.C++ supports overloads, templates, and virtual dispatch. Python supports runtime operator dispatch, duck typing, and subtype dispatch.

C++ is statically typed: an expression’s type is established before execution, with limited inference such as auto. Python is dynamically and strongly typed: names can be rebound to values of different types, but incompatible operations still raise errors. Type annotations in Python are primarily for tools and documentation; Python itself does not generally enforce them.

In ad-hoc polymorphism, overloaded functions or operators select among implementations. Parametric polymorphism uses a generic definition, such as a C++ template. Subtype polymorphism lets a derived object be used through a base interface; C++ uses virtual for dynamic dispatch, while Python methods dispatch dynamically by default. Duck typing asks whether an object supports the needed operations, rather than requiring a declared parent class.

Type inference derives types without spelling them out. C++ deduces some types locally; Hindley–Milner systems infer more general types. A Python type checker can infer and check annotations statically, but this is an external analysis rather than Python runtime enforcement.

Trap: “dynamic” does not mean “untyped”, and a Python annotation does not by itself reject a wrong value at runtime.

Near miss: two objects with a speak() method can be used by duck typing even if neither inherits from Animal; the shared operation, not ancestry, makes the call work.

7.3 Abstraction and encapsulation

A stable interface lets a component change internally without forcing every caller to change. Encapsulation groups state with the operations that preserve its rules.

In plain words: abstraction presents the useful operation and hides incidental detail. Encapsulation keeps related state and methods together; information hiding limits which implementation details callers should rely on.

Interface boundarycaller depends on contract, not representationRead it as: “callers use the promised behaviour without depending on the internal layout”.A contract describes valid inputs, observable results, and relevant errors.

C++ access specifiers (public, protected, private) are enforced by the compiler; a class defaults to private members while a struct defaults to public. Python relies more on convention: a leading underscore signals internal use. Double-leading underscores trigger name mangling to reduce accidental clashes; they do not make an attribute inaccessible to determined code.

Modules and packages organize code. Python modules are files; package behavior includes regular packages with __init__.py and namespace packages that may omit it. __all__ affects wildcard imports, not whether a name can be accessed directly. C++ headers declare interfaces and source files commonly contain definitions; namespaces organize names, while unnamed namespaces or internal linkage can limit visibility.

Python permits runtime introspection and monkey patching, which can help testing but can make invariants harder to maintain. C++ class layout and declarations are generally fixed by compilation, though dynamic libraries and polymorphism still allow runtime extension through designed interfaces.

Trap: do not present Python’s double underscore as a security boundary.

Near miss: placing a leading underscore on a name documents “internal”; it does not stop another module from importing or reading it.

7.4 Memory management

Allocated memory and other resources need clear ownership and a release point. The language’s memory model determines which mistakes it can prevent automatically.

In plain words: manual memory management makes the programmer responsible for releasing allocations. Automatic reclamation finds objects that are no longer reachable. RAII ties a resource’s lifetime to an owning C++ object.

Ownership disciplineacquire once · release once · do not use after releaseRead it as: “give each resource a clear owner and a clear end to its lifetime”.Ownership can be shared by an explicit design, but cycles and failure paths need attention.

In C, malloc/free pair allocation and release; in C++, new/delete exist, but modern C++ usually prefers automatic objects and standard containers. RAII releases resources in destructors when scope ends, including during exception unwinding. std::unique_ptr expresses exclusive ownership; std::shared_ptr shares reference-counted ownership; std::weak_ptr can observe shared objects without keeping them alive and can break ownership cycles.

CPython primarily uses reference counting and supplements it with cyclic garbage collection. Other Python implementations may use different strategies. Unreachable cycles can be reclaimed, but objects retained by live references are not garbage. Garbage collection does not replace deterministic cleanup for files or sockets; use context managers such as with open(...).

Common manual-management errors include leaks, dangling pointers, double frees, and out-of-bounds writes. Automatic collection reduces some lifetime errors but cannot prevent all memory growth or resource misuse.

Trap: a garbage collector cannot free an object that remains reachable through a live reference.

Near miss: two shared_ptr objects can keep each other alive in a cycle; reference counting alone cannot reduce either count to zero.

7.5 Compilation and execution

Source code is transformed into forms a runtime or processor can execute. Intermediate representations make analysis and optimization easier.

In plain words: a compiler translates a program. An interpreter executes instructions under a runtime. Many real systems combine both, so “compiled versus interpreted” is a spectrum rather than a clean divide.

A common C++ compiler pipelinesource → tokens → syntax tree → semantic checksIR → optimization → machine code → linkingRead it as: “parse source, check its meaning, optimize an intermediate form, then generate and link target code”.Compilers vary: stages can be combined, repeated, or omitted, and optimization is not guaranteed to improve every input.

CPython compiles source to bytecode and its virtual machine executes that bytecode; .pyc files cache compiled code for imports. The bytecode format and runtime details can vary by version and implementation. PyPy uses a tracing JIT for hot paths; Cython can compile selected Python-like code to native extensions.

Static Single Assignment form gives each assigned variable a single definition by creating versions such as x1 and x2. At a control-flow join, a phi-function selects the version supplied by the path taken. The phi is an intermediate representation concept, not necessarily a machine instruction.

Worked merge · SSA

  1. Start with x1 = a + b.
  2. If c > 0, define x2 = x1 + c; otherwise define x3 = x1 − c.
  3. At the join, x4 = phi(x2, x3) represents the value from the branch that ran.
  4. Use x4 in the following expression.

Trap: Python is not simply “interpreted without compilation”; bytecode compilation is part of ordinary execution.

Near miss: source-level variable x may be assigned more than once, but SSA creates a distinct version for each assignment.

7.6 Recursion and termination

Recursion expresses a solution through smaller instances. A correct design must both reach a directly solved case and return the intended result.

In plain words: every recursive function needs base case(s) and a recursive step that reduces the problem. A well-founded measure, such as a non-negative integer, proves there cannot be an infinite descending chain.

Factorialfact(0) = 1fact(n) = n × fact(n − 1) for integer n > 0Read it as: “zero factorial is one; otherwise multiply n by the factorial of one less”.The measure is n; this definition’s stated domain is the non-negative integers.

Worked trace · fact(3)

  1. Calls descend: fact(3) → fact(2) → fact(1) → fact(0).
  2. The base call returns 1.
  3. fact(1) returns 1; fact(2) returns 2; fact(3) returns 6.
  4. Each waiting call has its own arguments and pending multiplication in its call frame.

With multiple recursive branches, each must reduce a suitable measure. Naive Fibonacci revisits subproblems; memoization stores results so each distinct input is solved once, aside from dictionary and output costs.

Fibonacci with zero-based indexingF(0)=0, F(1)=1F(n)=F(n−1)+F(n−2) for n≥2Read it as: “each term from n=2 is the sum of the two preceding terms”.The lecture’s code returns n for n≤1; adding a cache avoids recomputing overlapping calls.

Recursion suits trees and divide-and-conquer: solve smaller inputs and combine results. Backtracking explores choices depth-first and returns when a branch cannot succeed. In mutual recursion, one measure must decrease across the call cycle. Iteration makes state explicit and can avoid call overhead and stack growth. Primitive recursion restricts recursion form; general recursion is more expressive, as Ackermann’s function illustrates.

Trap: a base case does not guarantee termination if some path skips it or fails to reduce the measure.

Near miss: the call f(n) inside f(n) is recursive syntax but gives no progress toward termination.

7.7 Induction and recursive algorithms

Induction proves statements about every input size or recursively built structure. Its assumptions mirror how a recursive algorithm uses results for smaller cases.

In plain words: weak induction uses the immediately preceding case; strong induction may use any smaller case; structural induction follows the constructors of a recursive structure.

Induction proof patternbase: P(n0); step: P(k) ⇒ P(k + 1)Read it as: “prove the starting case, then show a case implies its successor”.For structural induction on a tree, prove the empty case and then a node assuming the property for both children.

Worked proof · triangular numbers

  1. Claim: 1 + … + n = n(n + 1)2 for n ≥ 1.
  2. Base n=1: both sides equal 1.
  3. Assume 1 + … + k = k(k+1)/2.
  4. Add k+1: k(k+1)/2 + (k+1) = (k+1)(k+2)/2.
  5. This is the claim for k+1, so induction proves it for every n ≥ 1.

Weak induction assumes the immediately smaller case; strong induction may assume all smaller natural numbers; well-founded induction generalizes this to any relation with no infinite descending chain. The Ackermann function is a classic total computable function that is not primitive recursive. Under the lecture’s recurrence, A(4,1)=65,533, and A(4,2)=265,536−3, which has 19,729 decimal digits. General recursion, lambda-definability, and Turing computability describe equivalent classes of effectively computable functions; practical runtimes still impose resource limits.

Trap: when proving a recursive algorithm, match each code base case to a proof base and each recursive branch to the induction assumption it uses.

Near miss: “the result is true for k, so it is true for k+1” omits the algebra or program step that connects the two cases.

Exam-style problems

1 · References, lifetime, and abstraction · 20 minutes

Compare this Python code with a C++ object that owns a file handle.

  1. Trace a=[1,2]; b=a; c=a[:]; b.append(3). State the values and identities. (4 marks)
  2. Explain why a Python object is not simply “a value stored in the stack slot of its variable”. (3 marks)
  3. Describe how RAII releases the C++ file handle on normal return and exception exit. (3 marks)
  4. Explain why a Python double-underscore attribute is not equivalent to a C++ private member. (2 marks)
Show worked answer
  1. a and b refer to the same list, now [1,2,3]. c is a shallow copy of the outer list and remains [1,2]; the lists are distinct. §7.1
  2. Python names are bindings to objects managed by the runtime. Physical layout depends on the implementation; a call frame holds local bindings, and the language does not expose ordinary raw pointer arithmetic. §7.1
  3. The owning automatic object is destroyed when its scope exits. Its destructor closes the handle, including during exception unwinding. §7.4
  4. C++ private access is checked by the compiler. Python name mangling changes a name to reduce accidental clashes but deliberate access remains possible. §7.3

2 · Termination and correctness · 20 minutes

Consider recursive flattening of a nested list, and the triangular-number formula.

  1. Define a measure that decreases for recursive flattening and give its base case. (3 marks)
  2. State a structural induction proof shape for correctness on a nested list. (3 marks)
  3. Prove 1+…+n=n(n+1)/2 by induction for n≥1. (4 marks)
  4. Explain why tail-recursive factorial can still hit Python’s recursion limit. (2 marks)
Show worked answer
  1. Use the number of nested list nodes or total number of elements remaining. Empty list returns empty list; each recursive branch handles a proper sublist or advances past an element. §7.6
  2. Base: empty input flattens to empty. Step: assume the recursive result is correct for each nested sublist; concatenating scalar elements and those results in order gives the correct flattening. §7.7
  3. Base n=1 gives 1=1·22. Assume the formula for k. Then the next sum is k(k+1)2+(k+1)=(k+1)(k+2)2, the formula for k+1. §7.7
  4. Python does not guarantee tail-call optimization, so every recursive call keeps a frame until it returns. §7.7
