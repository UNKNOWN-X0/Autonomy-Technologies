Recursion and Dictionaries

Algorithms, Programming, and Data Representation · Module 23131 · Chapter 8

Recursion solves a problem by asking the same function to solve a smaller version, then uses the returned answer. Dictionaries pair keys with values, giving recursive programs a way to remember earlier work and organize data for lookup.

8.1 The recursive pattern

A loop repeats a block while its condition holds; recursion expresses repetition as a function calling itself on a smaller problem.

In plain words: recursion is a way to solve a problem by reducing it to a simpler instance of the same problem. A base case is small enough to answer directly. A recursive case makes progress toward that base case and combines its answer with the smaller answer.

Multiplication by repeated additionmult(a, 1) = amult(a, b) = a + mult(a, b − 1) for b > 1Read it as: “multiply a by b by adding a to the product of a and one fewer than b”. This version assumes a positive integer b.
def mult(a, b):
    if b == 1:
        return a
    return a + mult(a, b - 1)

For mult(5, 4), the recursive calls ask for mult(5, 3), then mult(5, 2), then the base mult(5, 1). The result returns as 5, 10, 15, then 20.

Worked example · factorial

  1. We need 4!. Use n! = n × (n − 1)!.
  2. Reduce: 4! = 4 × 3!, 3! = 3 × 2!, 2! = 2 × 1!.
  3. Base: 1! = 1, so return to the waiting calls: 2 × 1 = 2, 3 × 2 = 6, 4 × 6 = 24.
  4. Check: 4! = 4 × 3 × 2 × 1 = 24.

Trap: having a base case is not enough if some inputs never reach it. For every recursive call, name the quantity that gets smaller.

Near miss: return n * f(n) is recursive syntax, but the input never gets smaller, so it does not reach a base case. Change the call to f(n - 1) for positive n.

8.2 Tracing calls and proving progress

The function does not finish when it calls itself; each earlier call waits for its smaller call to return.

In plain words: Each call gets its own scope, or environment, for its parameter values. Calls stack up while the function goes deeper. When a base case returns, control moves back through the waiting calls, each completing its own calculation.

Factorial recurrencefact(1) = 1fact(n) = n × fact(n − 1) for n > 1Read it as: “the factorial of n is n times the factorial of n minus one”. The call stack stores the unfinished multiplications.

Worked trace · fact(4)

  1. Calls descend: fact(4) → fact(3) → fact(2) → fact(1).
  2. fact(1) returns 1.
  3. fact(2) returns 2 × 1 = 2.
  4. fact(3) returns 3 × 2 = 6.
  5. fact(4) returns 4 × 6 = 24.

One variable name such as n can appear in every call. These are separate bindings: n is 4 in the first frame, 3 in the next, and so on. A returned value travels back; the local name does not.

Sign check: state whether you are tracing the descent (calls) or the return (answers). Reversing them is a common source of wrong traces.

Near miss: writing only fact(1) = 1 and fact(4) = 24 skips the calls that justify the result. Include each intermediate input and return.

8.3 Induction and correctness

A trace shows one run. To reason that the recursive pattern works for every allowed input, match the program to an inductive argument.

In plain words: Mathematical induction proves a claim over a sequence of integer inputs. First prove the smallest case. Then assume the claim for a smaller input and use that assumption to prove it for the next input. Recursive correctness follows the same shape because each call relies on a smaller case.

Induction structureBase: prove P(n0).Step: assume P(k), prove P(k + 1).Read it as: “establish the first case, then show each true case makes the next one true”. The base value n0 must match the problem’s domain.

Worked proof · sum from zero to n

  1. Claim: 0 + 1 + … + n = n(n + 1)2.
  2. Base n = 0: both sides are 0.
  3. Assume the formula holds for k. Then the sum through k + 1 is k(k + 1)2 + (k + 1).
  4. Factor (k + 1): k(k + 1)2 + (k + 1) = (k + 1)(k + 2)2, which is the formula for k + 1.
  5. Therefore it holds for every integer n ≥ 0.

For recursive code, say what the function promises to return. Verify that promise at the base case. Then assume the smaller call returns its promised answer and show the current step transforms it into the right answer.

Trap: the induction hypothesis is for the smaller case k; do not assume the very statement for k + 1 that you are trying to prove.

Near miss: a proof that checks several values such as 0, 1 and 2 is evidence, not a proof for all n. The induction step covers the general next case.

8.4 Fibonacci and memoization

Some recursive definitions branch into more than one smaller call, so the same subproblem can be solved repeatedly.

In plain words: In the lecture’s rabbit model, the number at month n is the total from the previous month plus the new pairs produced from the count two months earlier. The naive recursive function rebuilds the same earlier counts in many branches. Memoization stores a result after calculating it so later calls can reuse it.

Fibonacci sequence used in the lecturefib(0) = 1 and fib(1) = 1fib(n) = fib(n − 1) + fib(n − 2) for n ≥ 2Read it as: “each later value is the sum of the previous two values”. This lecture indexes the first two values at 0 and 1, both equal to 1.
def fib(n, cache):
    if n in cache:
        return cache[n]
    answer = fib(n - 1, cache) + fib(n - 2, cache)
    cache[n] = answer
    return answer

cache = {0: 1, 1: 1}
print(fib(6, cache))  # 13

Worked example · cache Fibonacci values

  1. Start with {0: 1, 1: 1}; these are the base cases.
  2. To find fib(4), compute fib(3) and fib(2). The first needs fib(2) again.
  3. The first completed fib(2) stores 2. The later call finds it in the dictionary instead of expanding it again.
  4. Then fib(3) = 3 and fib(4) = 5. Check the sequence: 1, 1, 2, 3, 5.

Slides 40–43 report 11,405,773 recursive calls for naive fib(34) and 65 for the cached version, using the slides’ fib(1)=1, fib(2)=2 indexing. This guide uses a 0-based shift, so its call totals differ; compare algorithms only under the same convention. The important lesson is that caching avoids recalculating completed subproblems.

Trap: caching works only if a result depends on the function’s input, not on hidden changing state or side effects. The same key must mean the same answer.

Near miss: calculating answer but never assigning cache[n] leaves every future call to repeat the work. Store before returning.

8.5 Recursion on strings

A recursive input need not be a number. A string can become a smaller string by removing one or more characters.

In plain words: A palindrome reads the same forwards and backwards. After normalizing a phrase by removing punctuation and changing letters to lowercase, strings of length zero or one are palindromes. Otherwise, compare the first and last characters; if they match, check the inside.

Recursive palindrome testis_palindrome(s) = True when len(s) ≤ 1is_palindrome(s) = s[0] == s[−1] and is_palindrome(s[1:−1])Read it as: “the ends match and the inner string is a palindrome”. This rule is applied after normalization.

Worked example · “Able was I, ere I saw Elba”

  1. Normalize to ablewasiereisawelba.
  2. Compare outside characters: a == a. Recurse on blewasiereisawelb.
  3. Continue comparing pairs toward the centre; each pair matches.
  4. The remaining middle is length zero or one, so return True.

A phrase with a mismatched pair returns False immediately; there is no need to inspect the inside. This is a short-circuit and.

Trap: normalize once before the recursive helper. If punctuation is not removed, the comparison may stop at a comma or space.

Near miss: checking only the first and last characters accepts abca. The inside must also pass the recursive test.

8.6 Dictionaries

Parallel lists can store related fields, but every list must stay aligned and every lookup needs an index. A dictionary connects a key directly to its value.

In plain words: A dictionary stores key–value pairs. A key identifies one entry; a value holds its associated information. Keys are unique and must be hashable. Values may repeat and may be mutable, including lists or other dictionaries.

Core operationsd[key] gets the value or raises KeyErrord[key] = value adds or replaces an entrykey in d tests keys · del d[key] removes an entryd.keys() and d.values() give iterable viewsRead it as: “look up the value attached to this key”. Membership checks keys, not values.

Worked example · replace parallel lists

  1. Parallel form: names[i], grades[i], courses[i] must use matching indices.
  2. Dictionary form: grades = {'Joe': 'B', 'John': 'A+'}.
  3. grades['John'] evaluates to 'A+'; 'John' in grades is True.
  4. grades['Katy'] = 'A' adds an entry. del grades['Joe'] removes one.

Keys need to be hashable: their hash must remain stable while they are in the dictionary. Integers, strings and booleans are common keys; a tuple is usable if all its contents are hashable. A list is not hashable and cannot be a key. A float can technically be a key, but exact floating-point equality can make it a poor choice.

Python 3 dictionaries preserve insertion order. Updating an existing key keeps its position; deleting and re-adding it places it at the end. The lecture slide saying there is “no order” describes older Python behavior. Do not rely on order when the task is about key lookup unless the course explicitly asks about iteration order.

Trap: 'A+' in grades asks whether it is a key; use 'A+' in grades.values() to test values.

Near miss: grades['Sylvan'] does not mean “look up if present”; it raises KeyError. Test membership first when absence is expected.

8.7 Frequency analysis

Once a word can be used as a key, its value can record how many times it has appeared.

In plain words: A frequency dictionary maps each distinct word to its count. Read one word at a time: increment its old count if it exists, otherwise create it with count one. To find the most common words, first find the largest count, then collect every key with that value.

Frequency updatecounts[word] = counts[word] + 1 when the key existscounts[word] = 1 when it does notRead it as: “increment the count for a repeated word; start a new word at one”.
def lyrics_to_frequencies(words):
    counts = {}
    for word in words:
        if word in counts:
            counts[word] += 1
        else:
            counts[word] = 1
    return counts

Worked example · count and find a tie

  1. Input: ['sun', 'rain', 'sun', 'wind', 'rain'].
  2. After the loop: {'sun': 2, 'rain': 2, 'wind': 1}.
  3. The maximum value is 2.
  4. Collect every key whose value is 2: (['sun', 'rain'], 2). Both words tie.

The lecture’s words_often repeatedly finds the current most common words, records them if their count is at least the threshold, and deletes them from the dictionary. Deletion changes the dictionary passed in. If the caller must keep the original counts, make a copy first.

Trap: when several words share the maximum, return all of them. Stopping at the first key loses valid answers.

Near miss: testing if word in counts.values() checks whether the word equals a count; the membership test belongs on dictionary keys.

8.8 Choosing recursion

Recursion is not automatically the best implementation; it is especially useful when the input naturally contains nested levels.

In plain words: A list may contain another list, which contains another list, with no fixed depth. Recursion can process one level and call itself on each nested level. This is harder to express with a fixed number of loops. For a simple known sequence, iteration may be clearer and use less call-stack space.

Divide and conquerBreak a problem into smaller problems of the same kind.Solve each smaller problem, then combine their answers.Read it as: “reduce, solve, combine”. A recursive call must still make progress and have a base case.

Worked plan · flatten a nested list

  1. Input: [1, [2, [3]], 4].
  2. Base case: an item that is not a list is already one output element.
  3. Recursive case: for each item, append the item itself if it is simple; otherwise append the flattened result of that nested list.
  4. Combine in order to obtain [1, 2, 3, 4].

The lecture’s learning tasks practise this pattern with reverse, sum, product, count, palindrome, maximum, flatten, Fibonacci, merge of sorted lists, and subsets. Each problem needs its own input domain and base case; do not assume one recursive template solves all of them unchanged.

Trap: a recursive algorithm may be intuitive but costly if it solves the same subproblem repeatedly. Draw the call tree or cache shared results.

Near miss: flattening one level of [1, [2, 3]] gives [1, 2, 3], but it fails on [1, [2, [3]]]. The recursive case must handle a nested list at any depth.

Slips in the notes

These corrections preserve the lecture’s intended lesson while making the examples accurate for Python 3. Each is checked against the slide text and current language behavior.

  • Slide 13, induction step. The first instruction in the induction-step bullets says to assume the statement for n+1, but the next bullet correctly says to use the assumption for n. The hypothesis must be for n, which is then used to prove n+1. §8.3
  • Slide 19, Fibonacci docstring. The closing quotes in the displayed function are malformed, so the code does not parse as written. The guide uses a valid function definition. §8.4
  • Slide 32, dictionary views. The examples show keys() and values() as lists. In Python 3 they return dynamic view objects, not lists; convert a view with list(...) when a list is needed. §8.6
  • Slide 34, dictionary order. The slide says there is “no order to keys or values.” Python 3.7 and later guarantee insertion order for dictionaries. The lesson here is key-based lookup, not sorting; the guide states the modern rule explicitly. §8.6
  • Slide 34, keys. It says “immutable type” and lists floats and tuples. The exact requirement is hashability: a tuple is valid only if all its elements are hashable, while custom immutable objects may be hashable or not. §8.6
  • Slides 16–19 and 40–42, Fibonacci indexing. The rabbit table and slide 19 use fib(0)=fib(1)=1, while slides 40 and 42 use fib(1)=1, fib(2)=2. These are the same sequence with indices shifted by one. This guide follows the rabbit table’s 0-based convention. §8.4
  • Slide 43, call counts. The slide’s fib(34) totals use the later one-based indexing. With the guide’s 0-based indexing, the totals for the same argument differ; the reliable comparison is that naive recursion repeats subproblems while memoization reuses them. §8.4
